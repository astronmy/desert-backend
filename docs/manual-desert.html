01Introducción

Desert Backend centraliza la gestión de eventos, invitados e invitaciones, y conecta la confirmación desde la app con el control de acceso en puerta.

Panel Admin

Interfaz web para el equipo Desert: usuarios, eventos, invitaciones (alta manual e importación Excel) y listado de ingresos.

API

Endpoints para la app mobile (consulta + confirmación con selfie) y para el scanner de puerta (datos del invitado + check-in QR).

Flujo de negocio

1 Admin crea
evento e invitaciones
›
2 Invitado confirma
en la app + selfie
›
3 Scanner lee QR
y muestra datos
›
4 Se registra
el ingreso

Modelo de dominio

Evento

Casamiento, cumpleaños, graduación, corporativo o privado. Tiene fechas y muchas invitaciones.

Invitado

Persona identificada por documento (DNI o pasaporte). Puede tener varias invitaciones a distintos eventos.

Invitación + Acceso

Une invitado y evento con un código único. El acceso registra un único ingreso por invitación.

Estados de una invitación

Pending · Pendiente Confirmed · Confirmada Cancelled · Cancelada
  • Pendiente — creada, aún no confirmada por el invitado.
  • Confirmada — el invitado validó datos y envió selfie; lista para ingresar.
  • Cancelada — no puede usarse en app ni en puerta.

02Acceso al panel

El panel se usa con sesión web (email y contraseña). No hay registro público: los usuarios los crea otro administrador.

Iniciar sesión

  1. Abrí la URL del sistema (por ejemplo https://tu-dominio/login).
  2. Ingresá email y contraseña.
  3. Opcional: marcá “recordarme” para mantener la sesión en ese navegador.
  4. Al entrar correctamente vas al Dashboard (/admin/dashboard).

Entorno de demostración. Tras el seed inicial: email admin@deserteventos.com.ar / contraseña password. Cambiá la contraseña en producción.

Cerrar sesión

Desde el menú del panel usá la opción de salir. La ruta es POST /logout y requiere estar autenticado.

Mapa rápido del menú

Sección Ruta Para qué sirve
Dashboard /admin/dashboard Inicio tras el login
Eventos /admin/events CRUD de eventos e invitaciones
Usuarios /admin/users Administradores del sistema

03Usuarios administradores

Los usuarios del panel tienen acceso completo a la administración. No hay roles granulares: cualquier cuenta autenticada opera todo el admin.

Crear un usuario

  1. Andá a Usuarios → Crear.
  2. Completá nombre, email y contraseña (con confirmación).
  3. Guardá. El email debe ser único en el sistema.

Editar o eliminar

  • Editar — podés actualizar nombre, email y, si querés, una nueva contraseña.
  • Eliminar — borrá cuentas que ya no se usen. No podés eliminar tu propia sesión activa.
Buenas prácticas
  • Usá contraseñas fuertes y distintas por persona.
  • No compartas la cuenta genérica de demo en producción.
  • Revisá periódicamente el listado y eliminá accesos obsoletos.

04Eventos

Un evento es el contenedor principal: tiene nombre, fechas, tipo, e invita a un conjunto de personas.

Crear un evento

  1. Menú Eventos → Crear.
  2. Completá:
    • Nombre — ej. “Casamiento Pérez”.
    • Fecha inicio y fecha fin (la fin no puede ser anterior a la inicio).
    • Tipo — ver tabla abajo.
  3. Guardá. Desde el listado podés entrar a invitaciones y accesos de ese evento.

Tipos de evento

Valor Etiqueta Uso típico
wedding Casamiento Bodas y celebraciones nupciales
birthday Cumpleaños Fiestas de cumpleaños
graduation Graduación Egresos y actos académicos
corporate Corporativo Eventos de empresa
private Privado Otros eventos privados

Filtros del listado

Podés filtrar eventos por nombre, tipo y rango de fechas sobre la fecha de inicio.

05Invitaciones

Cada invitación vincula un invitado a un evento, genera un código único (base del QR) y atraviesa los estados pendiente → confirmada / cancelada.

Alta manual

  1. Abrí el evento → Invitaciones → Crear.
  2. Completá nombre, apellido, número de documento y tipo (dni o passport).
  3. Al guardar:
    • Si el documento es nuevo, se crea el invitado.
    • Si ya existe, se reutiliza (y se actualizan nombre/apellido si cambian).
    • Se genera un código de 8 caracteres (A–Z y 0–9).
    • Estado inicial: Pendiente.

Un mismo invitado no puede tener dos invitaciones en el mismo evento. Sí puede estar invitado a varios eventos distintos.

Importación Excel / CSV

Ideal para listas largas. Desde el evento: Importar. Podés descargar la plantilla CSV de ejemplo.

Columna Aliases aceptados Ejemplo
Nombre Nombre, first_name, name Juan
Apellido Apellido, last_name Pérez
DNI DNI, documento, document_number 30111222
  • Formatos: .xlsx, .xls, .csv (máx. 10 MB).
  • La importación usa siempre tipo de documento DNI.
  • DNI nuevo → crea invitado + invitación. DNI existente → reutiliza. Ya invitado al evento → omite.

Detalle, edición y selfie

  • Ver detalle — datos del invitado, código, estado y selfie (si confirmó).
  • Editar — podés corregir datos del guest y cambiar el estado. Si pasás a confirmada se mantiene/asigna confirmed_at; si no, se limpia.
  • Filtros — nombre, documento, código y estado.

06Accesos en puerta

El listado de accesos del admin muestra quién ya ingresó a un evento. El registro en vivo lo hace el scanner vía API (capítulo 08).

Consultar ingresos desde el admin

  1. Abrí el evento → Accesos.
  2. Vas a ver cada ingreso con snapshot de nombre, documento, código y hora.
  3. Filtrá por nombre, documento, código o rango de fechas de ingreso.
Regla clave

Solo hay un acceso por invitación. Un segundo intento desde el scanner se rechaza.

Requisito

La invitación debe estar Confirmada antes de poder registrar el ingreso.

Qué ve el personal de puerta (vía scanner)

  • Datos del invitado y del evento.
  • Selfie de confirmación (si existe).
  • Si ya ingresó y la hora del primer acceso.

07API — App mobile

Base: {APP_URL}/api. Sin token: el acceso se autoriza con el código de invitación. Límite: 30 solicitudes/minuto.

GET /api/invitations/{code} Datos básicos

Devuelve evento, invitado y estado. El código se normaliza a mayúsculas.

HTTPSignificado
200Invitación encontrada
404Código inexistente
410Invitación cancelada
 
{
  "code": "L6QXJO5F",
  "status": "pending",
  "event": { "id": 1, "name": "Casamiento Pérez", … },
  "guest": { "first_name": "Juan", "document_number": "30111222", … },
  "confirmed_at": null,
  "selfie_url": null
}
POST /api/invitations/{code}/confirm multipart/form-data

El invitado confirma asistencia, actualiza nombre y envía selfie. Solo si está pending.

CampoReglas
first_nameRequerido, máx. 255
last_nameRequerido, máx. 255
document_numberRequerido; debe coincidir con la invitación
id_typedni o passport
selfieImagen requerida, máx. 5 MB
HTTPSignificado
200Confirmada correctamente
404No encontrada
409Ya estaba confirmada
410Cancelada
422Validación o documento no coincide

08API — Scanner

Endpoints para la puerta. Límite: 60 solicitudes/minuto. Flujo recomendado: consultar /entry y luego registrar con POST /accesses.

GET /api/invitations/{code}/entry Puerta · consulta

Igual que la consulta de app, más el bloque access ((has_entered / accessed_at). Permite invitaciones pendientes; bloquea solo las canceladas. 

{
  …
  "selfie_url": "https://…/storage/invitations/1/selfie.jpg",
  "access": {
    "has_entered": false,
    "accessed_at": null
  }
}
POST /api/accesses application/json

Registra el check-in. Body: { "code": "L6QXJO5F" }

HTTPSignificado
201Acceso registrado
404Invitación no encontrada
409Ya ingresó (incluye accessed_at)
410Invitación cancelada
422Aún no confirmada

Secuencia típica

App mobile                         Backend                      Scanner
   |                                  |                            |
   |-- GET /invitations/{code} ------>|                            |
   |-- POST …/confirm (selfie) ------>|                            |
   |                                  |                            |
   |                                  |<-- GET …/entry ------------|
   |                                  |    (foto + ¿ingresó?)      |
   |                                  |<-- POST /accesses ---------|
   |                                  |    { "code": "…" }         |

09Glosario y referencia

Glosario

Código / QR
Identificador único de 8 caracteres de la invitación. Se lee en la app y en la puerta.
Invitado (Guest)
Persona con documento único (DNI o pasaporte). Puede tener varias invitaciones.
Invitación
Vínculo guest + evento, con código, estado y selfie opcional.
Selfie
Foto enviada al confirmar; se muestra en puerta para validar identidad.
Acceso
Registro de ingreso (check-in). Máximo uno por invitación.
has_entered
Indicador booleano de si el invitado ya pasó por la puerta.

Códigos HTTP frecuentes

Código Cuándo aparece
200 / 201 Operación exitosa (consulta / acceso creado)
404 Código de invitación inexistente
409 Conflicto: ya confirmada o ya ingresó
410 Invitación cancelada (Gone)
422 Validación fallida o invitación aún pendiente

Notas operativas

  • Las selfies viven en almacenamiento público; hace falta php artisan storage:link.
  • APP_URL define la base de las URLs de selfie.
  • Los mensajes de la API están en español.
  • Fuera de alcance actual: auth por token (Sanctum) y envío automático de códigos por WhatsApp/email.
